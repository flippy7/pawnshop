# Контракт консольного запуску

**Задача**: 002. Контракт майбутньої реалізації, не протокол уже виконаних запусків.

## Виклик і режими

`java -Dfile.encoding=UTF-8 -Dsun.stdout.encoding=UTF-8 -Dsun.stderr.encoding=UTF-8 -cp out pawnshop.Main [режим]`

| Аргумент | Поведінка | Код завершення |
| --- | --- | --- |
| Відсутній або all | Послідовно чотири маршрути FR-011 | 0, якщо всі очікування виконані |
| verify | Позитивні й негативні перевірки за quickstart із контролем даних та станів | 0, якщо всі перевірки виконані |
| fault-check | Контрольовано неочікувана помилка перед першим бізнес-маршрутом | 1, негайне завершення |
| Інший аргумент або зайві аргументи | Українське пояснення допустимих режимів | 2, сценарії не запускаються |

Довільне введення, меню, мережа та файли даних відсутні. all і verify використовують детерміновані дані. Незалежні приклади мають власні об'єкти та унікальні id у межах запуску.

## Чотири маршрути all

1. **Оформлення та викуп**: подання → оцінка 1000 → договір 800/840 до 2026-12-15 → локальна перевірка false → Ready → видача → Active → платіж 840 → Redeemed. Одна видача, одне погашення, одне повернення.
2. **Продовження й викуп**: окремий договір із тими самими умовами → Active → строк 2027-01-15 → строк 2027-02-15 → платіж 840 → Redeemed. Одна видача за весь цикл; repaymentAmount весь час 840.
3. **Викрадення**: окремий id у локальному stolenItemIds → Draft → Rejected. Перевірка й відмова показані; видачі, погашення та повернення немає.
4. **Некоректні дії**: окремі потрібні об'єкти; передчасна/повторна видача, платіж 839, рівний/раніший строк, дії після завершення. Кожна очікувана відмова пояснена, дані незмінні, наступна незалежна перевірка виконується. Повний перелік граничних випадків перевіряється verify.

## Повідомлення та канали

Заголовок кожного маршруту позначає його номер і призначення. stdout містить українські повідомлення про подання, оцінку, перевірку та її результат, оформлення, видачу, продовження, погашення, повернення, очікувані відмови й підсумок. Кожне повідомлення називає дію, доречний id, суму чи дату та результат. Англійські ідентифікатори й назви станів дозволені всередині українського пояснення.

Приклади змісту: «Договір L1: видано 800.00 грн»; «Договір L1: запропоновано 841.00 грн, належить 840.00 грн; погашення виконано»; «Відмовлено: 839.00 грн менше належних 840.00 грн». Пунктуація не є умовою приймання; сутність, числа й порядок — є. Гроші показуються з двома десятковими знаками; дати — ISO YYYY-MM-DD.

StolenItemCheckService показує локальну перевірку та boolean-результат українською. Cashier показує успішні фінансові імітації тільки після завершення відповідної операції договору. LoanAgreement виконує правила без фінансового друку. Результат Rejected означає відмову, а не успішне оформлення.

Неочікувана помилка виводить українське пояснення в stderr і негайно завершує процес кодом 1. Наступних маршрутів та загального повідомлення успіху немає. У fault-check контрольна помилка виникає після службового повідомлення «Контроль неочікуваної помилки», до заголовка першого маршруту.

Очікувана відмова перехоплюється лише в позначеному негативному прикладі. Непередбачений виняток, неправильна причина відмови або невиконана перевірка результату не перетворюються на успішний запуск.

## Контракт предметних операцій

Сигнатури, залежності, передумови та переходи визначено у [data-model.md](../data-model.md). Методи залишаються void там, де це задано UML. Некоректні аргументи спричиняють IllegalArgumentException, недопустимі стани — IllegalStateException. Викрадення — особлива очікувана відмова: спершу Rejected, потім виняток. Відсутність результату перевірки залишає Draft; непередбачена помилка сервісу зупиняє звичайну демонстрацію.

Для verify контрольований виняток тестового сервісу локально перехоплюється саме як очікуваний результат перевірки атомарності. Це не дозволяє приховувати неочікувані помилки реальних маршрутів.

## Уточнення I1 та A2

Виявлення викрадення — окремий результат Draft → Rejected; незмінність стану стосується решти відхилених операцій.

Ідентифікатори навчальних об’єктів — непорожні рядки без пробільних символів. null, порожній рядок і рядки з пробільними символами відхиляються. Порівняння точне, з урахуванням регістру, без обрізання пробілів або зміни регістру: I1 та i1 різні, повторне I1 означає ту саму річ у межах запуску.

## Проміжне приймання

Після T020–T021 доступні verify та верхній обробник помилок: код 0 означає успіх лише реалізованого набору US1, який розширюється в US2/US3; код 1 — помилку. Повний контракт режимів завершується в US4. Це не приймання всього прототипу.
