# Контрольний список якості специфікації: UML-модель системи «Ломбард»

**Мета**: Перевірити повноту та якість вимог перед плануванням.
**Створено**: 2026-11-15
**Функціональність**: [Специфікація](../spec.md)

## Якість змісту

- [x] CHK001 Немає самостійно обраних деталей реалізації, фреймворків або API;
  задані користувачем формати та навчальні обмеження збережено як вимоги до результату.
- [x] CHK002 Зміст зосереджено на навчальній цінності та бізнес-потребах.
- [x] CHK003 Сценарії й результати описані зрозуміло для студента та викладача;
  спеціальні терміни потрібні лише для перевірки прямо заданих вимог до моделі.
- [x] CHK004 Усі обов'язкові розділи шаблону заповнені, порядок і рівні заголовків збережені.

## Повнота вимог

- [x] CHK005 Немає невирішених питань або маркерів потреби в уточненні.
- [x] CHK006 Вимоги однозначні та перевірювані, мають ідентифікатори FR-001–FR-023.
- [x] CHK007 Критерії успіху вимірювані, мають ідентифікатори SC-001–SC-007.
- [x] CHK008 Критерії успіху описують перевірювані результати без вибору інструментів реалізації.
- [x] CHK009 Сценарії приймання визначені для всіх чотирьох історій.
- [x] CHK010 Граничні випадки охоплюють дані, перевірку речі, повторні операції,
  погашення, продовження та неузгодженість документів.
- [x] CHK011 Межі поточного етапу та майбутньої функціональності явно розділені.
- [x] CHK012 Припущення та залежність від конституції визначені.

## Готовність функціональності

- [x] CHK013 Кожна функціональна вимога має спосіб приймання в історіях,
  бізнес-таблиці або критеріях успіху; зіставлення наведено нижче.
- [x] CHK014 Історії охоплюють усі основні сценарії та всі п'ять результатів.
- [x] CHK015 Вимоги забезпечують вимірювані результати SC-001–SC-007.
- [x] CHK016 Не додано коду, алгоритму генерації або інфраструктурних рішень;
  рішення щодо інструментів відкладені до планування.

## Примітки

Перевірку виконано 2026-11-15. Результат: 16 із 16 пунктів виконано.
Блокувальних недоліків та відкритих уточнень немає.
Це перевірка вимог, а не підтвердження існування чи коректності майбутніх діаграм.

Формати PlantUML, Mermaid, XLSX, імена типів і вимоги до ООП збережено на пряму
вимогу користувача. Обмеження Java, консолі та DI походять із конституції.
Тому CHK001 і CHK016 перевіряють відсутність додаткових рішень щодо реалізації,
а не вилучення цих обов'язкових вимог. Обґрунтований контракт `IStolenItemCheck`
узгоджує задану залежність із DIP; це припущення явно записане у специфікації.
