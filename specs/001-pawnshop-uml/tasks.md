## Формат і домовленості щодо шляхів

Кожне завдання має формат `- [ ] TNNN [P?] [USn?] Опис із шляхом`.
`[P]` дозволяє одночасне виконання лише після завершення перелічених залежностей.
US1–US4 відповідають чотирьом історіям spec.md. Шляхи відраховуються від кореня репозиторію.
`%TEMP%/pawnshop-uml-001-review/` — тимчасовий каталог перевірки, у PowerShell
отримується через `Join-Path $env:TEMP 'pawnshop-uml-001-review'`.
Тимчасові журнали й зображення не є додатковими обов'язковими результатами.

## Залежності та порядок виконання

Граф без циклів (стрілка означає «потрібне завершення»):

```text
T001 → T002 → T003 → T004
T004 → T005 → T006                            (US1)
T004 → T007 → T008 → T009 → T010              (US2)
T010 → T011 ─┐
T010 → T012 ─┴→ T013                          (US3)
T010 → T014 → T015 → ... → T023 → T024        (US4)
T006 + T010 + T013 + T024 → T025 → T026 → T027
```

US1 та US2 незалежні після спільної основи. US3 й US4 залежать від завершеної US2,
оскільки перевіряються за фактичною class.mmd, але не залежать одна від одної.
Пріоритети історій збережені: US1/US2 — P1, US3/US4 — P2.
Перевірки, що пишуть спільний validation.md, виконувати послідовно,
навіть якщо підготовка їхніх джерел відбувалася паралельно.
