# Контракт результатів генерації

Контракт стосується файлів для студента й викладача; мережевого API немає.
Вхід — spec.md та data-model.md. Вихід — п'ять файлів нижче.

## Текстові діаграми

| Шлях | Формат і обов'язковий зміст |
| --- | --- |
| docs/usecase.puml | PlantUML, початок і кінець документа, межа «Ломбард», три ролі, сім операцій; викуп і продовження окремі |
| docs/class.mmd | Mermaid classDiagram; 7 класів, 2 інтерфейси, усі члени та зв'язки з data-model.md |
| docs/sequence.mmd | Mermaid sequenceDiagram; подання, оцінка, створення, перевірка, оформлення, видача; альтернативи відмови, викупу й продовження |
| docs/state.mmd | Mermaid stateDiagram-v2; початковий/кінцевий псевдостани, стани та умови з data-model.md |

UTF-8, англійські aliases/імена типів, українські видимі пояснення.
Файли Mermaid містять безпосередній текст, без обгортки Markdown.
Для final та override використати видимі примітки з сигнатурою.
Повідомлення-виклики відповідають методам отримувача; повернення не є новими методами.
Створення показує конструктор, а початкові об'єкти можна оголосити як вже створені.
Спадкування та реалізація не замінюють залежностей, зумовлених параметрами.

## CRC-книга

Шлях: `docs/crc.xlsx`. Справжній XLSX без макросів, формул, зовнішніх посилань.
Рівно дев'ять аркушів з назвами типів із data-model.md; службовий порожній аркуш видалити.
На кожному: A1:B1 — об'єднана назва типу; A2 — «Обов'язки класу»;
B2 — «З ким співпрацює»; з рядка 3 — український зміст, англійські імена співпрацівників.
Ширина колонок орієнтовно 60 і 50 символів, перенесення тексту, вирівнювання зверху,
виділені заголовки, межі картки, область друку A:B за фактичними рядками,
масштаб друку одна сторінка завширшки. Перевірити, що весь текст видимий.
Аркуш для інтерфейсу явно пояснює контракт, а для абстрактного класу — спільні обов'язки.
Співпраця покриває реєстр зв'язків; опосередкування та успадкування позначаються словами.

## Приймання та помилки

Приймання вимагає: усі файли наявні й непорожні; синтаксис чотирьох джерел
прийнятий локальним засобом відображення; XLSX повторно читається та відкривається
без відновлення; 9 типів і карток збігаються; усі переходи й виклики узгоджені.
Помилка будь-якого пункту блокує приймання комплекту, а не маскується зображенням.
Тимчасові зображення потрібні для візуальної перевірки, не є шостим обов'язковим результатом.

## Перевірка простежуваності

Для кожного рядка таблиці операцій data-model.md перевірити відповідний use case,
метод і зв'язки class, виклик sequence, подію/дію state та відповідальність CRC.
Не вимагати однакових назв бізнес-підписів і методів, але вимагати однозначної відповідності.
Повнота — 100% операцій, типів, модельних посилань та сценаріїв приймання специфікації.
